# Admin Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A separate admin web app (`apps/admin`) covering UC025–UC028, backed by new read-only admin endpoints in workflow-service and workspace-service and new Gateway routes.

**Architecture:** Read-only admin endpoints in each service, guarded by the JWT `system_role=ADMIN` claim and isolated in new files so existing monitoring/workspace code paths are untouched. The Gateway adds `/api/admin/*` routes with its existing edge `requireAdmin` check. `apps/admin` is a standalone Vite app with copied design tokens, its own small API client and session handling.

**Tech Stack:** Spring Boot + JdbcTemplate/JPA + Flyway (Java 21), NestJS + Fastify + zod, React 19 + Vite + Tailwind v4 + React Query + react-router 7, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-21-admin-web-design.md`

## Global Constraints

- Branch `feature/admin-web`; one tested commit per task; `git commit -m "summary" -m "description"`, description ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Maven: always `JAVA_TOOL_OPTIONS=-Duser.timezone=UTC ./mvnw verify` from the service folder. Known environment-only failures are listed in `CLAUDE.md`; anything else is a regression.
- NestJS lint without rewriting files: `pnpm --dir services/api-gateway exec eslint "{src,test}/**/*.ts"`.
- Admin paging: `size` 1–100, default 20; `page` ≥ 0. Execution range ≤ 90 days. `ids` ≤ 100 UUIDs. Name search `q` ≤ 100 chars. Summary `hours` 1–168, default 24.
- Admin responses never contain execution `input`, `output`, node payloads, or unredacted error messages (reuse `ExecutionQueryAdapter.sanitizeString` and the 300-char cap from `MonitoringQueryAdapter`).
- Runs of soft-deleted workflows and soft-deleted workspaces are excluded, as in monitoring.
- `apps/admin` dev port `5174`; Gateway CORS gains `http://localhost:5174` and `http://127.0.0.1:5174`. Dependency versions copied from `apps/web/package.json`; no new libraries.
- No `console.log` in production code; no secrets in logs, tests, or the work log.
- GitNexus `impact`/`detect_changes` currently segfault. Retry the CLI at the start of each task; if it still fails, confirm callers by text search and say so in the commit description (user-approved fallback for the spec commit; ask again before code commits if the user has not extended it).

## Review Focus

1. A USER token sent straight to workflow-service or workspace-service (bypassing the Gateway) must get 403, not data. Tests in Tasks 1 and 2.
2. `ids`/`ownerId`/`workspaceId` that are not UUIDs, or more than 100 `ids`, must give 400, not 500. Tests in Tasks 2 and 3.
3. Name search containing `%`, `_` or `!` must match literally (same escape as `findAccessibleWorkspaces`). Test in Task 2.
4. An expired access token mid-session must refresh once and retry; a failed refresh must land on `/login` without a loop. Tests in Task 4.
5. Executions whose workflow was deleted must not appear in the list or detail. Test in Task 1.
