## 4. Bối cảnh và quyết định nền tảng

### Database và kết nối

- Supabase không còn là database mục tiêu. Các biến Supabase trong `.env.example` đã được comment để giữ tham khảo mà không còn được dùng mặc định.
- Cấu hình mẫu có năm nhóm biến `*_DB_*`: `IDENTITY`, `WORKSPACE`, `WORKFLOW`, `BOT`, `NOTIFICATION`.
- Neon phải dùng pooled endpoint (hostname có hậu tố pooler) và TLS. Ứng dụng được cấu hình theo `sslmode=require`.
- Docker Compose map biến database theo từng service; gateway không còn dựa vào Supabase URL.
- Không ghi giá trị endpoint, user, password hoặc URL đầy đủ vào log. Những giá trị này chỉ nằm trong `.env` cục bộ/secret store của môi trường.

### Thời gian

- Neon database đang trả thời gian `GMT`/UTC. Đây là lựa chọn lưu trữ chuẩn cho backend.
- JPA dùng `Instant`; cột timestamp dùng `TIMESTAMPTZ`; Hibernate JDBC timezone được đặt `UTC`.
- Chuyển đổi sang `Asia/Saigon` sẽ thực hiện tại DTO/response/read layer khi cần hiển thị, không đổi timezone của dữ liệu lưu trữ.
- Local Testcontainers từng lỗi khi JVM sử dụng `Asia/Saigon` nhưng PostgreSQL không chấp nhận tên timezone đó. Test được chạy với `JAVA_TOOL_OPTIONS=-Duser.timezone=UTC`; không thay đổi timezone máy người dùng.

### Data ownership

- Thiết kế entity được lấy từ Notion `Class Model Source of Truth — V1`: `User`, `UserSession`, `OAuthAccount`; enum `SystemRole`, `UserStatus`, `OAuthProvider`.
- Các liên kết đến user từ service khác tiếp tục là scalar UUID, không tạo JPA cross-service association.
- `avatarStorageKey` là object key, không phải URL public.

Lệnh tái lập an toàn (không chứa giá trị secret):

```powershell
docker run --rm --env-file .env postgres:16-alpine sh -c 'export PGPASSWORD="$IDENTITY_DB_PASSWORD" PGSSLMODE=require; psql -h "$IDENTITY_DB_HOST" -p "${IDENTITY_DB_PORT:-5432}" -U "$IDENTITY_DB_USERNAME" -d "$IDENTITY_DB_NAME" -c "select current_database(), current_user;"'
```

Lưu ý: trong PowerShell, lệnh phải dùng đúng tên biến không có ký tự escape thừa. Nếu lệnh in `host=` rỗng, kiểm tra tên biến trong `.env` và cách shell mở rộng biến trước khi kết luận lỗi mạng/Neon.

## 9. Trạng thái bàn giao và việc tiếp theo

### Có thể tiếp tục ngay

1. Tạo use case/service + controller cho register/login, dùng `RegisterUserRequest`, `PasswordEncoder`, entity/repository và error contract hiện có.
2. Thiết kế và triển khai JWT access/refresh token: issuer, claim, expiry, verification filter/resource server, revoke/rotation policy và test tích hợp.
3. Tạo response DTO và MapStruct mapper khi API contract được chốt; giữ conversion timestamp sang `Asia/Saigon` ở response/read layer.
4. Khi có use case cache thực tế, thêm Redis runtime configuration, key namespace, serialization, TTL, health/connection test và observability; không chỉ dựa vào dependency đã thêm.
5. Rà soát các service còn lại để tạo database/migration riêng theo các nhóm `*_DB_*`, sau khi owner của từng domain chốt model.
6. Review diff, chạy test phù hợp, cập nhật GitNexus index nếu cần, rồi tạo commit/PR tách theo concern.

### Cần quyết định hoặc xác nhận

- Chốt JWT strategy: symmetric secret hiện có hay asymmetric key/issuer chuẩn; nơi quản lý và rotation secret.
- Chốt API contract public cho register/login/refresh/OAuth trước khi implement controller.
- Chốt use case đầu tiên cần Redis để tránh thêm cache/TTL không có mục đích.
- Xác định quy trình dọn hoặc giữ năm user development seed ở môi trường shared.

### Hướng dẫn cho AI agent / thành viên tiếp nhận

- Đọc log này, `docs/development/SETUP.md`, `git status` và model Notion trước khi sửa persistence/auth.
- Không đổi kiểu lưu thời gian từ `Instant`/UTC sang local time. Chỉ format `Asia/Saigon` ở ranh giới response/UI khi API yêu cầu.

- Giữ ranh giới service: chỉ UUID scalar khi tham chiếu user từ domain khác, không thêm quan hệ JPA xuyên service.
- Tôn trọng phạm vi dependency-only của MapStruct/Redis cho đến khi có yêu cầu implement. Nếu bắt đầu code, cập nhật log bằng bằng chứng runtime/test thật.
